# 03. 要件（Kaizen Board MVP）

## 利用者

| 役割 | 誰 | 主な操作 |
|---|---|---|
| 投稿者 | 現場の全員 | 困りごと・提案を投稿する。自分の投稿の状況を見る |
| 対応者 | 改善担当・ライン長 | ステータス変更、担当・対応コメントの記入 |
| 閲覧者 | 管理職 | ボードと件数を見る |

## ユーザーストーリー（MVP）

1. 投稿者として、タブレットから **1 分以内**に困りごとを投稿したい。忙しい現場で続けるため。
2. 投稿者として、投稿が**どの段階にあるか**をボードで見たい。出しっぱなしに感じないため。
3. 対応者として、新着（受付）を一覧で見て**ステータスを変えたい**。対応漏れを防ぐため。
4. 対応者として、**担当者名と対応コメント**を残したい。誰が何をしたか後で追えるため。
5. 対応者として、**見送り**にした理由を残したい。同じ提案が繰り返されないため。
6. 閲覧者として、**ステータス別・区分別・場所別の件数**を見たい。活動量を把握するため。
7. 管理者として、投稿は **kintone のレコード**として残したい。既存の集計・通知・権限管理を使うため。

## MVP でやらないこと（Phase 4 送り）

- 写真添付（kintone 添付ファイル API の 2 段階アップロードが必要）
- ログイン・権限管理（LAN 内限定を前提）
- 通知（メール / チャット）
- オフライン投稿（PWA のキャッシュは閲覧のみ）
- kintone プロセス管理との連動（ステータスは通常のドロップダウン）
- 多言語

## 非機能

| 項目 | 要件 |
|---|---|
| 端末 | PC（Chrome / Edge）、タブレット（Safari / Chrome）。画面幅 768px 以上を主対象、375px でも投稿可能 |
| 操作性 | 投稿は必須項目 3 つ（区分・場所・タイトル）まで。文字入力はタイトルのみ必須 |
| 性能 | 一覧 200 件まで 2 秒以内。kintone 取得はページング（500 件 / 回） |
| 可用性 | kintone 障害時はエラー表示のみ（投稿は失敗として明示、二重投稿を防ぐ） |
| セキュリティ | API トークンはサーバの `.env` のみ。ブラウザには渡さない |
| 運用 | 区分・場所・ステータスの選択肢は `shared` で一元管理。kintone 側の選択肢と一致させる |

## 成功指標（現場試行 4 週）

| 指標 | 目標 | 測り方 |
|---|---|---|
| 投稿数 | 週 5 件以上 | kintone レコード数 |
| 一次対応 | 受付 → 検討中 が 3 営業日以内 80% | `posted_at` と更新日時の差 |
| 完了率 | 完了 + 見送り が 30 日で 50% 以上 | ステータス集計 |
