# 00. 構想候補と評価

## 目的

「自分が乗れる（納得して作り切れ、現場に価値が出る）」アプリ構想を 1 つに絞る。
候補はあなたの領域（製造業の業務改善 / kintone / Electron 製 Mission Bridge）から逆算して挙げた。
**実際の現場課題は不明**なので、下の決定シートで補正すること。

## 評価軸（5 点満点、合計 25）

| 軸 | 見るポイント |
|---|---|
| 現場インパクト | 使われた場合に減る時間・ロス・ミスの大きさ |
| 実現しやすさ | 1 人で MVP を 2〜4 週で出せるか。必要な端末・権限が揃うか |
| kintone 親和性 | レコード蓄積 / API で自然にデータが貯まるか |
| 既存資産の活用 | Mission Bridge や既存 kintone アプリと繋がるか |
| 自分が乗れるか | 作りたい・使わせたいと思えるか（あなたが記入） |

## 候補

### A. チョコ停・停止記録アプリ（Downtime Logger）

- **何をする**: 設備 / ライン脇の端末で「停止理由をタップ → 開始 / 終了」を記録。kintone に蓄積し、理由別パレート・時間帯別の可視化を出す。
- **誰が使う**: オペレーター（記録）、ライン長・改善担当（分析）。
- **価値**: 停止ロスの定量化ができ、改善テーマ選定が数字で決まる。
- **リスク**: 現場端末の用意、記録が続く UI 設計（3 タップ以内が目安）。
- **仮採点**: インパクト 5 / 実現 3 / kintone 5 / 既存資産 3 / 乗れるか ?

### B. 改善提案・困りごとボード（Kaizen Board）

- **何をする**: 現場から QR / タブレットで困りごと・提案を投稿。kintone で管理し、ステータス（受付→検討→実施→効果確認）をボードで見せる。
- **誰が使う**: 全員（投稿）、改善担当（進捗管理）。
- **価値**: 提案が埋もれない、対応の見える化で提案数が増える。
- **リスク**: 運用ルール（誰が一次対応するか）がないと止まる。
- **仮採点**: インパクト 3 / 実現 5 / kintone 5 / 既存資産 3 / 乗れるか ?

### C. 変化点（4M）管理アプリ

- **何をする**: 人・設備・材料・方法の変更を登録し、影響工程・確認項目・承認をワークフロー化。品質異常発生時に変化点を遡れる。
- **誰が使う**: 工程管理・品証・ライン長。
- **価値**: 変化点起因の不良を早期に切り分けられる。監査対応にも効く。
- **リスク**: 承認フローの要件が重くなりがち。MVP の切り方が難しい。
- **仮採点**: インパクト 4 / 実現 2 / kintone 4 / 既存資産 2 / 乗れるか ?

### D. シフト引継ぎ・日報アプリ

- **何をする**: 交代時の申し送り（設備状態・未完了作業・注意点）を定型入力し、次シフトが確認済みチェック。kintone に蓄積。
- **誰が使う**: 各シフトのリーダー。
- **価値**: 口頭・紙の引継ぎ漏れをなくす。過去の申し送りを検索できる。
- **リスク**: 既存の紙・チャット運用からの移行抵抗。
- **仮採点**: インパクト 3 / 実現 4 / kintone 5 / 既存資産 3 / 乗れるか ?

### E. Mission Bridge 拡張（kintone レコード横断の業務ナビ）

- **何をする**: 既存の Mission Bridge に、kintone 複数アプリを跨いだ「今日やるべき業務」の集約と、各業務の手順ナビを追加。
- **誰が使う**: 事務・管理部門の担当者。
- **価値**: 既存資産の延長で導入コストが低い。
- **リスク**: Mission Bridge の現状仕様が本リポジトリからは**不明**。別リポジトリとの関係整理が先。
- **仮採点**: インパクト ? / 実現 ? / kintone 5 / 既存資産 5 / 乗れるか ?

## 暫定推奨

**A（チョコ停・停止記録）** を第一候補、**B（改善提案ボード）** を「A の前提が揃わない場合」の第二候補とする。

根拠:

- A は成果が「停止時間 ○○ 時間削減」と数字で示せ、改善担当の武器になる。
- 入力が単純なため MVP を小さく切れる（1 ライン × 理由 10 件 × 1 画面）。
- kintone にレコードが貯まる形が最も素直で、既存の集計・通知機能を流用できる。
- 一方、現場端末が用意できない場合は A が成立しないので、その場合は B に切り替える。

**前提（未確認）**: 現場に置ける端末（タブレット / 既設 PC）があること。Wi-Fi が届くこと。

## 決定シート（あなたが埋める）

```

成功の数字         : （例: 4 週間で記録率 80% 以上、停止理由 Top3 が特定できる）
使う端末           : （例: 既設 Windows PC / iPad / スマホ）

```
