# 構想メモ(壁打ち記録)

更新: 2026-09-05

## 目的

品質管理室が各部門から**紙ベース**で受け取っている検査依頼をデジタル化する。
これが最優先タスク。

## 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| アプリ形態 | **ブラウザ + 社内 LAN の Node.js 同期サーバー** | 多人数同時編集が必須要件。Electron 単体+ローカル保存では成立しない(v0.1 で採用した Electron は廃止) |
| 同時編集 | tldraw sync(`@tldraw/sync` / `@tldraw/sync-core`)を自前サーバーで運用 | 競合解決・差分配信を自作しない |
| ボードの単位 | 部門ごと 1 ボード(初期値: 品質管理室 / 製造1課 / 製造2課)+ 任意追加 | まず複数人で触って要件を固めるため |
| ユーザー識別 | 名前の自己申告 | 最小構成。社内アカウント連携は後段 |
| キャンバス | tldraw SDK を採用 | 描画エンジン自作を避け、UI/UX のカスタマイズ(独自ツールバー・独自図形)に工数を集中 |
| 開発順序 | ①キャンバス → ②リスト・画像一覧 → ③kintone 連携 | ユーザー指定 |
| 技術構成 | Vite + React + TypeScript(client)/ Node.js + express + ws(server) | Mission Bridge と技術資産を共有しやすい構成 |

## 現在の実装(v0.3 プロトタイプ)

- **サイドバーの依頼リスト**: ボード上の依頼カードを状態別件数つきで一覧表示。行クリックでカードへズーム
- **依頼カードの編集フォーム**: カードを選択するとサイドバーに状態・品番・ロット・数量・依頼者・依頼日・備考の入力欄。編集は即時に全員へ同期
- **依頼者・依頼日の自動記録**: カード作成時にユーザー名と当日を記録。既存ボードは props マイグレーションで補完
- **図面・写真の取り込み**: 画像をドラッグ&ドロップするとサーバーに保存され、全員に表示(E2E で検証済み)

- **多人数同時編集**: 2 ブラウザ間で図形が双方向に同期、相手のカーソルと名前が見える(E2E で検証済み)
- **ボード一覧と作成**: 名前入力 → ボード選択。新規ボード作成可
- **サーバー永続化**: 最後の人が抜けたら JSON スナップショット保存。次回開いた時に復元
- 独自縦型ツールバー(既定ツールバーを差し替え、日本語ラベル)
- 不要な既定 UI(メインメニュー、ページメニュー、共有、デバッグ)を非表示
- 独自図形「検査依頼カード」(`request-card`): 部門・品番・ロット・数量・ステータス
  - props は将来 kintone レコード項目に 1:1 で写せる粒度
- tldraw アイコン・フォントをバンドル同梱(オフライン動作)

## 未決事項・要確認

- [ ] 同期サーバーを置く社内サーバー(Node.js 常駐可能な PC/サーバーの有無)
- [ ] 社内アカウント(Microsoft 365 等)でのログインが必要か
- [ ] 紙の依頼書の項目一覧(現物の写真 or スキャンが欲しい)
- [ ] 依頼の流れ(受付→割当→検査→結果返却のどこまでをスコープに含めるか)
- [ ] 依頼元部門の環境(PC/タブレットの有無、kintone アカウントの有無)
- [ ] 1日あたりの件数、依頼部門数
- [ ] 画像一覧の「画像」の正体(図面、現物写真、依頼書スキャン)
- [ ] キャンバスの主用途(図面への注釈 / 手書き依頼書の再現 / カード配置による進捗管理)
- [ ] tldraw のライセンス条件(本番利用時のキー要否・費用)
- [ ] Mission Bridge の実際の技術構成

## 次の候補タスク

1. 依頼リストのスプレッドシート化(セル直接編集、並べ替え、絞り込み、CSV 出力)
2. 画像一覧ペイン(ボード上の図面・写真をサムネイルで一覧、クリックでズーム)
3. 依頼カードと図面の紐付け(カードから関連図面へジャンプ)
4. ボードの一覧に「誰が今見ているか」を表示
5. kintone への保存(サーバー側から REST API 経由)
6. 認証(社内アカウント連携)と閲覧権限
