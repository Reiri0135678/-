# 構想メモ(壁打ち記録)

更新: 2026-09-05

## 目的

品質管理室が各部門から**紙ベース**で受け取っている検査依頼をデジタル化する。
これが最優先タスク。

## 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| アプリ形態 | **ブラウザ + 社内 LAN の Node.js 同期サーバー** | 多人数同時編集が必須要件。Electron 単体+ローカル保存では成立しない(v0.1 で採用した Electron は廃止) |
| 同時編集 | **Yjs(MIT)+ y-websocket 互換の自前サーバー** | 競合解決は Yjs に任せ、認証・権限・永続化はサーバーで制御 |
| ボードの単位 | 部門ごと 1 ボード(初期値: 品質管理室 / 製造1課 / 製造2課)+ 任意追加 | まず複数人で触って要件を固めるため |
| ユーザー識別 | users.json による名前+パスワード(無ければ自己申告) | 社内アカウント(M365 等)連携は auth.ts の差し替えで対応 |
| kintone 連携 | サーバー側から REST API。shape id を外部キーに作成/更新 | ボードが正、kintone は蓄積・検索・他システム連携用 |
| Mission Bridge との関係 | **埋め込む**(WebContentsView / webview)。Mission Bridge のログインユーザーを共有鍵経由で QC Board に代理ログイン | ユーザー指定。QC Board は独立 Web アプリのまま保ち、Mission Bridge は表示とユーザー受け渡しだけ担う |
| キャンバス | **自作(Konva で描画)**。v0.1〜v0.5 の tldraw は v0.6 で撤去 | ライセンス費用・透かし・キーを一切絡めないため(ユーザー指定)。必要機能に絞って実装 |
| 開発順序 | ①キャンバス → ②リスト・画像一覧 → ③kintone 連携 | ユーザー指定 |
| 技術構成 | Vite + React + TypeScript(client)/ Node.js + express + ws(server) | Mission Bridge と技術資産を共有しやすい構成 |

## 現在の実装(v0.9 プロトタイプ)

- **ホワイトボードの快適さ**(v0.9): 移動時のスナップとガイド線、矢印の端点の図形への吸着(端点ハンドルで付け外し、吸着先の移動に追従、削除で解除)、描画途中の線のリアルタイム共有
- **ホワイトボードの残り機能**(v0.9): 相手の選択範囲の表示、文字装飾、グループ化・ロック、複数ページ、コメント(スレッド・解決)
- **操作系の充実**(v0.10): コピー/貼り付け、整列・等間隔、重なり順、右クリックメニュー、図形の種類・線種・矢頭・直線・ラベル、PNG 保存、検索、追従(発表者モード)
- **区画・ミニマップ・版・雛形**(v0.11): 区画(中の図形ごと移動、常に背面)、ミニマップ、版の保存と復元(サーバーに Yjs 更新を保存。復元は全員に同期し、復元前も自動保存)、現場向け雛形 7 種

- **一覧の強化**(v0.9): キーボード移動、行チェックによる一括変更(状態・優先度・担当・アーカイブ)、納期超過・至急の強調、部門・納期超過・期間の絞り込み、集計ビュー(タイル+部門別・担当別・納期超過)、表示列の選択と列幅変更、ドロワーの高さ変更、CSV 取り込み(紙・Excel からの移行用。受付番号で更新)

- **デザイン刷新**(v0.8): 紙色の下地・テラコッタのアクセント・明朝系の見出し(Anthropic ブランド配色)。汎用的な青系 UI をやめ、CSS 変数に集約

- **検査結果**(v0.8): 合格/条件付合格/不合格と所見。判定者・判定日を自動記録。kintone・CSV にも出力
- **状態遷移ルール**(v0.8): 現在の状態から移れる状態だけ選択可。`STATUS_TRANSITIONS` で変更
- **通知**(v0.8): Webhook(Teams / Slack / JSON)へ新規依頼・状態変更・検査結果・担当割当を送信
- **バックアップ・ローテーション・自動アーカイブ**(v0.8): 定期バックアップ(世代管理)、履歴ログのローテーション、N 日経過の自動アーカイブ
- **PDF 図面**(v0.8): ブラウザ側でページを画像化して取り込み(依頼フォーム・ドロップ・貼り付け)
- **タブレット**(v0.8): サイドバー折りたたみ、ピンチズーム

- **受付番号**(v0.7): サーバーが `QC-YYYY-NNNN` を自動採番。カード見出し・一覧・kintone の外部キーに使える
- **担当・希望納期・優先度**(v0.7): カード項目に追加。至急は赤帯で強調
- **依頼フォーム**(v0.7): 依頼者向けの入力画面。図面添付つきで送信すると受付番号が返る。ボード一覧とボード上部からリンク
- **状態の拡張と取消**(v0.7): 保留・差戻し・取消を追加。カードは物理削除せず取消状態にして記録を残す
- **アーカイブ**(v0.7): 完了・取消カードをボードから外し、一覧と kintone に残す
- **変更履歴**(v0.7): サーバーが追記型ログに記録(誰が・いつ・何を)。カード編集画面で参照

- **キャンバスを自作に置き換え**(v0.6): Konva 描画 + Yjs 同期。ライセンス費用・透かし・キー無し。
  選択・移動・拡縮・回転、ペン、蛍光、消しゴム、文字、付箋、矢印、四角、楕円、画像、依頼カード、範囲選択、複製、
  取り消し/やり直し(自分の操作のみ)、ズーム・パン、他の人のカーソル、画像のドロップ/貼り付け。バンドルは 4.3MB → 0.65MB
- 閲覧者(viewer)の書き込みはサーバーが破棄する(クライアント改変でも書けない)

- **依頼一覧のスプレッドシート**(下部ドロワー): セル直接編集、列見出しで並べ替え、全文検索、状態フィルタ、CSV 出力(BOM 付き、Excel 対応)
- **図面・写真ギャラリー**(サイドバー): サムネイル一覧、クリックでズーム、紐付け先カード数の表示
- **カードと図面の紐付け**: カードから「図面を紐付け」→ ギャラリーかキャンバスの画像をクリック。カードに 📎 件数、関連図面のサムネイルから移動
- **kintone 連携**: 「kintone へ送信」でカードをレコードとして作成/更新(shape id を外部キーに)。レコード番号をカードに書き戻し全員に同期。設定は config/kintone.json、モックで検証済み
- **認証と閲覧権限**: users.json による名前+パスワード。役割 admin / member / viewer。viewer はサーバー側で読み取り専用。users.json が無ければオープンモード

- **サイドバーの依頼リスト**: ボード上の依頼カードを状態別件数つきで一覧表示。行クリックでカードへズーム
- **依頼カードの編集フォーム**: カードを選択するとサイドバーに状態・品番・ロット・数量・依頼者・依頼日・備考の入力欄。編集は即時に全員へ同期
- **依頼者・依頼日の自動記録**: カード作成時にユーザー名と当日を記録。既存ボードは props マイグレーションで補完
- **図面・写真の取り込み**: 画像をドラッグ&ドロップするとサーバーに保存され、全員に表示(E2E で検証済み)

- **多人数同時編集**: 2 ブラウザ間で図形が双方向に同期、相手のカーソルと名前が見える(E2E で検証済み)
- **ボード一覧と作成**: 名前入力 → ボード選択。新規ボード作成可
- **サーバー永続化**: 最後の人が抜けたら JSON スナップショット保存。次回開いた時に復元
- 独自縦型ツールバー(既定ツールバーを差し替え、日本語ラベル)
- 不要な既定 UI(メインメニュー、ページメニュー、共有、デバッグ)を非表示
- 独自図形「検査依頼カード」(`request-card`): 部門・品番・ロット・数量・ステータス
  - props は将来 kintone レコード項目に 1:1 で写せる粒度

## 次の候補タスク

1. 実データでの検証: 紙の依頼書に合わせたカード項目の見直し(現状は仮の項目)
2. kintone 実環境での接続確認(現状はモック検証のみ)
3. ボード一覧に「誰が今見ているか」と最終更新を表示
4. 通知(新規依頼・状態変更を kintone 通知や Teams などへ)
5. 監査ログ(誰がいつ何を変えたか)

## 構想の補足と改善点(2026-09-05 レビュー)

v0.4 まで作った上で、構想として抜けている点・弱い点を業務面と技術面に分けて整理する。
「決」は既に決めた前提、「要」はユーザーの判断が必要、「案」は私の提案。

### A. 業務面

| # | 論点 | 現状 | 補足・改善案 | 区分 |
|---|---|---|---|---|
| A1 | **受付番号** | v0.7 で実装(`QC-YYYY-NNNN` をサーバー採番) | kintone の外部キーは設定で shape id / 受付番号を選択可 | 決 |
| A2 | **状態遷移** | v0.8 で遷移ルールを実装(既定: 検査中→完了/保留/差戻し/受付、完了→検査中(再検査)など) | ルールは仮。運用に合わせて `STATUS_TRANSITIONS` を調整。役割別の制限(誰が動かせるか)は未実装 | 要 |
| A3 | **担当・納期・優先度** | v0.7 で実装 | 一覧で並べ替え可。至急はカードに赤帯 | 決 |
| A4 | **検査結果の記録** | v0.8 で合否・所見・判定者・判定日を実装 | 報告書(PDF)の添付と依頼者への自動返却は通知(A7)で代替。測定値の構造化(項目ごとの数値)は要件次第 | 決 |

### B. 技術面

| # | 論点 | 現状 | 補足・改善案 | 区分 |
|---|---|---|---|---|
| B1 | **ライセンス** | 全依存 MIT(v0.6 で tldraw 撤去) | 費用・透かし・キー不要。解決済み | 決 |
| B2 | **保存方式** | Yjs バイナリ + v0.8 で定期バックアップ(世代管理)を実装 | バックアップ先は別ドライブ・別サーバーにするのが望ましい | 決 |
| B3 | **変更履歴・監査ログ** | v0.7 で実装、v0.8 でローテーション追加 | 改ざん防止(追記専用の保護)は運用設計で決める | 決 |
| B4 | **通信の暗号化** | 社内 LAN の平文 HTTP | LAN 内限定なら許容範囲だが、Cookie に Secure が付かない。リバースプロキシ(Caddy 等)で HTTPS 化すると設定 1 行で済む | 要 |
| B5 | **サーバーの常駐** | 手動起動 | Windows なら NSSM でサービス化、Linux なら systemd。自動再起動と起動時ログ | 案 |
| B6 | **画像の肥大化** | 削除されたカード・画像のファイルが残る | 参照されないアップロードの定期削除(GC)。上限 50MB/ファイルも用途に合わせ見直す | 案 |
| B7 | **kintone 連携の詳細** | 一方向。外部キーは shape id または受付番号(設定) | 取消・アーカイブも状態として送られる。複製カードは新しい受付番号が付き別レコードになる(意図どおり) | 決 |
| B8 | **タブレット表示** | v0.8 でサイドバー折りたたみとピンチズームを実装 | 実機での操作感の確認が必要 | 決 |
| B9 | **同時接続規模** | 数十人程度を想定 | Yjs + 単一 Node プロセスで 1 ルーム数十人は問題なし。全社規模なら複数プロセス化を検討 | 決 |
| B10 | **オフライン** | サーバー停止中は編集不可 | 業務上許容できるか。許容できないなら B5 の自動再起動と B2 のバックアップで十分 | 要 |
