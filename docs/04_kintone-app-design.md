# 04. kintone アプリ設計

管理者への作成依頼書としてもそのまま使える。**アプリ ID・ドメイン・トークンはここに書かない**（`.env` のみ）。

## アプリ: 改善提案・困りごと（1 アプリ構成）

| 表示名 | フィールドコード | 型 | 必須 | 選択肢 / 備考 |
|---|---|---|---|---|
| タイトル | `title` | 文字列（1行） | ○ | 60 文字以内 |
| 区分 | `kind` | ドロップダウン | ○ | `困りごと` / `改善提案` |
| 場所 | `area` | ドロップダウン | ○ | 現場に合わせて設定（初期値: `第1ライン` / `第2ライン` / `倉庫` / `事務所` / `その他`） |
| 詳細 | `detail` | 文字列（複数行） |  | 2000 文字以内 |
| 投稿者 | `reporter` | 文字列（1行） |  | 任意。空なら「匿名」扱い |
| ステータス | `status` | ドロップダウン | ○ | `受付` / `検討中` / `実施中` / `完了` / `見送り`。初期値 `受付` |
| 担当者 | `owner` | 文字列（1行） |  | 対応者が入力 |
| 対応コメント | `response` | 文字列（複数行） |  | 見送り理由もここに書く |
| 投稿日時 | `posted_at` | 日時 | ○ | アプリが投稿時刻を明示的に入れる |
| 完了日時 | `completed_at` | 日時 |  | 完了 / 見送りに変えた時刻 |

- レコード番号（`$id`）を投稿 ID として使う。
- 作成者 / 更新者は API トークン経由だと「Administrator」等になるため、人の記録には `reporter` / `owner` を使う。

## API トークン

| 用途 | 権限 | 備考 |
|---|---|---|
| BFF 用 | レコード閲覧・追加・編集 | 削除は付けない |

## 一覧（kintone 側、任意）

- 「新着（受付）」: `status = 受付`、`posted_at` 降順
- 「対応中」: `status in (検討中, 実施中)`

## 選択肢を変える時

`shared/src/options.ts` と kintone の選択肢を**同時に**変える。BFF は起動時に kintone のフォーム定義を取得して差分があれば警告ログを出す（Phase 2 で実装）。

## 依頼テンプレート（管理者向け）

```
件名: kintone アプリ作成と API トークン発行の依頼

1. 上表のフィールドで「改善提案・困りごと」アプリを作成
2. API トークンを 1 つ発行（閲覧・追加・編集。削除なし）
3. アプリ ID とトークンは口頭またはパスワード管理ツールで共有（メール・チャット本文には書かない）
```
