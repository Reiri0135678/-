Electron 実装リファレンス UI操作との対応

⌂ 入口カタログkintone6162
デモ 61・62 で触れた Electron 固有の部分を、業務アプリ（Mission Bridge 想定）で必要になる順にまとめる。原則：renderer は普通のブラウザとして書き、OS・ファイル・通信の権限が要るものだけ main に置いて IPC で呼ぶ。デモと ui-kit は renderer 側でそのまま動く。このページは参照用で、コードはこのページでは実行されない。

0. 構成の原則（contextIsolation + preload）

renderer から Node を直接触らせない。preload で必要な関数だけ window.api として公開し、renderer はそれを呼ぶ。これで UI コードはブラウザで動くものと同じになり、デモ・ui-kit がそのまま使える。

// main.js
const win = new BrowserWindow({ width: 1200, height: 800,
  webPreferences: { preload: path.join(__dirname, 'preload.js'), contextIsolation: true, nodeIntegration: false, sandbox: true } });

// preload.js
const { contextBridge, ipcRenderer } = require('electron');
contextBridge.exposeInMainWorld('api', {
  kintone: (req) => ipcRenderer.invoke('kintone:request', req),         // 通信は main 経由（13 参照）
  onMenu: (name, fn) => ipcRenderer.on('menu:' + name, () => fn()),     // 62
  windowState: { get: () => ipcRenderer.invoke('win:getState') },
});

// renderer.js（普通のブラウザコード）
const records = await window.api.kintone({ method: 'GET', path: '/k/v1/records.json', params: { app: 1, query: 'limit 100' } });

1. ウィンドウ状態の永続化（位置・サイズ・最大化） ← 81 ワークスペース永続化の OS 側

閉じる前に getBounds() を保存し、起動時に復元する。ディスプレイ構成が変わっていると画面外に出るので、screen で表示範囲内か検証してから使う。

const { screen } = require('electron');
const saved = store.get('win');                                         // 自前の JSON 保存（electron-store 等でも可）
const fits = saved && screen.getAllDisplays().some(d => {
  const a = d.workArea; return saved.x >= a.x && saved.y >= a.y && saved.x + saved.width <= a.x + a.width && saved.y + saved.height <= a.y + a.height; });
const win = new BrowserWindow({ ...(fits ? saved : { width: 1200, height: 800 }) });
if (saved?.maximized) win.maximize();
const save = () => store.set('win', { ...win.getNormalBounds(), maximized: win.isMaximized() });
win.on('close', save); win.on('resize', debounce(save, 500)); win.on('move', debounce(save, 500));

2. フレームレスウィンドウとタイトルバー ← 61

自前タイトルバーは -webkit-app-region: drag。Windows/Linux で OS の最小化・最大化・閉じるボタンだけ残したいなら titleBarOverlay。ダブルクリックで最大化は自前実装。

new BrowserWindow({ frame: false, titleBarStyle: 'hidden', titleBarOverlay: { color: '#0f172a', symbolColor: '#fff', height: 32 } });
// renderer: .titlebar { -webkit-app-region: drag; height: 32px; padding-right: 140px; /* overlay のボタン分を空ける */ }
//           .titlebar button, .titlebar input { -webkit-app-region: no-drag; }
// preload: dblclick → ipcRenderer.send('win:toggleMaximize')
ipcMain.on('win:toggleMaximize', e => { const w = BrowserWindow.fromWebContents(e.sender); w.isMaximized() ? w.unmaximize() : w.maximize(); });

3. メニュー・アクセラレータと画面内ショートカットの衝突 ← 62, 35

アプリメニューの accelerator は renderer の keydown より先に取られる。同じキーを両方に登録しない。方針：アプリ全体の操作（新規、保存、終了）はメニュー側、画面内の操作（矢印移動、セル編集）は renderer 側。globalShortcut はアプリが背面でも効くので、業務アプリでは基本使わない。

const template = [{ label: 'ファイル', submenu: [
  { label: '新規', accelerator: 'CmdOrCtrl+N', click: (_, w) => w?.webContents.send('menu:new') },
  { label: '保存', accelerator: 'CmdOrCtrl+S', click: (_, w) => w?.webContents.send('menu:save') },
  { type: 'separator' }, { role: 'quit' } ] },
  { label: '表示', submenu: [{ role: 'reload' }, { role: 'toggleDevTools' }, { type: 'separator' }, { role: 'resetZoom' }, { role: 'zoomIn' }, { role: 'zoomOut' }] }];
Menu.setApplicationMenu(Menu.buildFromTemplate(template));

4. IPC の型と失敗の扱い ← 57 楽観的更新, 79 オフライン

invoke/handle は Promise を返すので、renderer 側は fetch と同じ感覚で await できる。main で throw した Error は renderer に届く（メッセージのみ）。チャンネル名は '領域:動詞' で統一し、一覧を1ファイルにまとめる。

// channels.js（main と preload で共有）
module.exports = { KINTONE_REQUEST: 'kintone:request', WIN_GET_STATE: 'win:getState', FILE_OPEN: 'file:open' };
// main
ipcMain.handle(CH.KINTONE_REQUEST, async (e, req) => { validate(req); return kintoneClient.request(req); }); // 入力は必ず検証
// renderer
try { await window.api.kintone(req); } catch (err) { toast.show(err.message, { kind: 'error' }); /* 57: 巻き戻し */ }

5. 複数ウィンドウ ← 85

同一アプリの複数 BrowserWindow は同じオリジンなので、renderer 同士は BroadcastChannel（ui-kit の sync.js）で同期できる。main が「真実の状態」を持つ設計なら、BrowserWindow.getAllWindows() に配信する（62 のコード）。ウィンドウごとに webContents.id を持つので、送信元を除外できる。

6. ファイルの受け渡し ← 59 ファイルドロップ

OS からのドロップは renderer の drop で受ける（59 と同じ）。パスが必要なら webUtils.getPathForFile(file)（preload 側）。逆にアプリからエクスプローラへドラッグして出すのは webContents.startDrag。保存ダイアログは main の dialog。

// preload
contextBridge.exposeInMainWorld('api', { pathOf: (file) => webUtils.getPathForFile(file), saveAs: (name, data) => ipcRenderer.invoke('file:saveAs', name, data) });
// main
ipcMain.handle('file:saveAs', async (e, name, data) => { const { filePath } = await dialog.showSaveDialog({ defaultPath: name }); if (filePath) await fs.promises.writeFile(filePath, data); return filePath; });

7. 認証情報の保存 ← 13 kintone

API トークンやパスワードを平文の JSON に置かない。safeStorage で OS のキーチェーンに紐づけて暗号化する。renderer には渡さず、main が通信時にだけ復号して使う。外部サービスへのログイン手順（システムブラウザ＋PKCE）は 120、置いてはいけない場所の一覧は 121。現場機器（バーコード・秤・プリンタ）を扱うなら 126：ブラウザ単体では Chromium 系に限られるため、Electron が本命になる。

const { safeStorage } = require('electron');
const enc = safeStorage.encryptString(token).toString('base64');     // 保存はこれ
const token = safeStorage.decryptString(Buffer.from(enc, 'base64'));   // 使うときだけ復号（main 内）

8. 表示倍率・DPI ← 55 devicePixelRatio

Ctrl+ホイールの既定ズームは renderer の内容ごと拡大する。図面ビュー（43）で自前ズームをするなら、既定ズームと衝突しないよう wheel で ctrlKey 付きのものを preventDefault するか、webContents.setVisualZoomLevelLimits(1, 1) でピンチズームを止める。Canvas は devicePixelRatio を見て内部解像度を上げる（55）。

9. 二重起動・起動時間・開発者ツール

if (!app.requestSingleInstanceLock()) app.quit();                      // 二重起動禁止。2つ目は既存ウィンドウを前面へ
app.on('second-instance', () => { const w = BrowserWindow.getAllWindows()[0]; w?.focus(); });
win.once('ready-to-show', () => win.show());                            // 白い画面を見せない（show:false で作る）
if (!app.isPackaged) win.webContents.openDevTools({ mode: 'detach' });
