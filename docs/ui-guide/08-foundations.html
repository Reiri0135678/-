F2イベントの発火順と伝播 capture → target → bubble / stopPropagation

イベントは「外側から内側へ（capture）→ 当たった要素（target）→ 内側から外側へ（bubble）」の順に流れる。addEventListener(type, fn, true) で capture 側に登録できる。stopPropagation() はそこから先へ流さない。preventDefault() は伝播ではなく「ブラウザの既定動作」を止める。この2つの違いが最重要。

操作：内側の箱をクリック。ログに順序が出る。チェックで「中央で stopPropagation」を有効にすると、外側の bubble が来なくなる。

F3transform と left/top の違い レイアウト vs 合成

位置を動かす方法は2つあるが、コストが違う。left/top を変えるとブラウザはレイアウト計算（周囲の要素の位置も再計算）をやり直す。transform は最終的な合成段階で動かすだけで、レイアウトは走らない。だからデモは全部 transform で動かしている。opacity も同じく安い。

操作：300個の箱を同じ動きで走らせ、フレーム時間を比べる。差が小さい端末もあるが、要素数が増えるほど開く。

F7重なり順とスタッキングコンテキスト z-index が効かない理由

z-index は「同じスタッキングコンテキスト内」でしか比較されない。親に transform・opacity<1・filter・position + z-index などがあると、そこで新しいコンテキストができ、子の z-index がいくら大きくても親の外の要素を追い越せない。ツールチップやドロップダウンが「下に潜る」原因の9割はこれ。

操作：チェックで左の親に transform を付ける。子の z-index:999 が右の z-index:1 に負ける。
