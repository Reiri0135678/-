103入力装置と当たり判定 pointer / any-pointer / 44px

マウスは 1px を狙えるが、指は狙えない。@media (pointer: coarse) で見た目を変えずに当たり判定だけ広げるのが定石（::before を伸ばす）。指で使う画面は 44×44px 以上が目安。タッチとマウスの両方が繋がる端末（現場のタブレット＋マウス）もあるので、`any-pointer` で「どちらも来る」前提にする。

104修飾キーの差 Ctrl / ⌘ / Alt / Option

Windows の Ctrl は macOS の ⌘（metaKey）。判定を間違えると Mac で全く効かない。画面に出す表記も OS で変える（Mac に「Ctrl+S」と出ていると迷う）。navigator.userAgentData.platform で判定し、無い環境では navigator.platform にフォールバックする。

操作：キーを押す。押された修飾キーと、この OS での正しい表記が出る。

105画面の高さ vh / svh / lvh / dvh

スマートフォンではスクロールに応じてアドレスバーが伸縮するため、100vh は「バーが隠れたときの高さ」＝画面より大きく、下がはみ出す。svh（最小＝バーが出ている状態）、lvh（最大）、dvh（今の実際の高さ、変化に追従）で正確に指定できる。全画面のパネルやモーダルは dvh か svh。

操作：スマートフォンで開いてスクロールすると差が出る。下の帯は同じ「10%」の高さを4種類の単位で描いたもの。

107日本語入力（IME）の途中を無視する compositionstart / isComposing

この資料で最も実害が出やすい項目。日本語を打つと、変換確定前の「かな」の段階でも input と keydown が飛ぶ。対策しないと、①検索が「けん」「けんさ」…と無駄に走る ②Enter による変換確定を「決定」と誤認して、確定した瞬間にフォームが送信される、が起きる。event.isComposing（または compositionstart/end）で変換中は無視するのが正解。

操作：日本語入力に切り替えて「けんさ」と打ち、変換して Enter。左（対策なし）は途中で何度も反応し、Enter を確定として扱ってしまう。

108「戻る」で閉じる CloseWatcher / Android のバックキー

Android では戻る操作でモーダルを閉じるのが期待される挙動。従来は履歴に push して popstate で閉じる小細工が要った。CloseWatcher は「Esc・Android の戻る・ブラウザの戻るジェスチャー」をまとめて1つのイベントで受け取れる。<dialog> と popover は最初からこの挙動を持つ（自前のオーバーレイにだけ必要）。

操作：開いて Esc（Android なら戻るキー）で閉じる。

109スクロールバーの差 scrollbar-gutter / scrollbar-width / overscroll-behavior

Windows のスクロールバーは場所を取る（出た瞬間に中身が 15px ずれる）。macOS と iOS は重なって表示され消える。scrollbar-gutter: stable で最初から場所を空けておくとズレが起きない。overscroll-behavior: contain は「内側を末端まで送ったら親までスクロールが伝わる」現象（モーダル内スクロールの定番の不快さ）を止める。
