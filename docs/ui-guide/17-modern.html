96状態を保ったまま移動する Element.moveBefore()

32 の並べ替えは insertBefore で DOM を動かす。これは「一度取り外して付け直す」動作なので、iframe は再読み込みされ、フォーカスや再生中の動画・アニメーション・popover の開閉状態が失われる。moveBefore() は接続を保ったまま移動するため、状態が壊れない。グリッド内の埋め込み表示や入力途中の行を動かす場面で効く。

98長い処理で UI を止めない scheduler.yield() / long-animation-frame

54 は「描画をまとめる」話だったが、逆に重い計算そのものが長すぎると、その間クリックもスクロールも効かなくなる（F10 の longtask）。await scheduler.yield() を挟むと、その場でブラウザに順番を譲り、続きは優先的に再開される（setTimeout(0) より順番待ちが短い）。CSV 変換や一括計算はこれで分割する。

操作：3方式を試す。左の丸が回り続けるかを見る。総時間はどれもほぼ同じで、違うのは「途中で画面が動くか」だけ。

-

① と ②③ の差は決定的（画面が 1.6 秒止まるか、止まらないか）。② と ③ の差は、ページが暇なときは小さい。混んでいるとき（他のタスクや入力があるとき）に、③ は待ち行列の後ろに回されず優先的に再開される点で有利になる。

99業務コードが短くなる標準API Object.groupBy / toSorted / Promise.withResolvers / AbortSignal.any / Intl

集計・並べ替え・非同期・書式で、自前のユーティリティを書かずに済むようになったもの。元の配列を壊さない（toSorted）、グループ化が1行（Object.groupBy）、外から解決できる Promise（withResolvers：ダイアログの戻り値待ちに最適）、複数の中断条件を束ねる（AbortSignal.any：タイムアウト＋ユーザー中断）。

操作：実行して結果を見る。コードを開いて書き方を確認する。

101並び順を CSS から使う sibling-index() / sibling-count()

操作：「行を足す」→「再生」。足した行にも自動で正しい遅延が付く。
