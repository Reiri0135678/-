# 素案：サードパーティ連携（Y層）と 3D モデリング・編集操作（Z層）

作成 2026-09-06 ／ 現行 113 項目（A〜E・M・X 層）への追加提案。

> **この素案は実装済み**（2026-09-06）。成果物は [`20-integration.html`](20-integration.html)（Y層 114〜127）と
> [`21-3d.html`](21-3d.html)（Z層 128〜143）、および依存ゼロの WebGL2 レンダラ [`assets/mini3d.js`](assets/mini3d.js)。
> 依存方針は下記の選択肢のうち **「併用」**（自前実装で原理を示し、three.js / `<model-viewer>` の参考コードを併記）を採用した。
> 以下は決定に至った調査と設計の記録として残す。

## 結論

- **Y層 114〜127（14項目）：外部サービス・外部機器との連携**。iframe と postMessage、認証（OAuth 2.1 + PKCE）、CORS、Webhook、現場機器（バーコード・計測器）まで。
- **Z層 128〜143（16項目）：3D の操作と編集**。カメラ操作からギズモ・スナップ・計測・断面・分解図・AR まで。**43〜51 の座標変換と修飾キーの考え方をそのまま 3D に持ち上げる**構成にし、既存層と地続きにする。
- 3D は**自前実装（WebGL2、依存なし）で原理を示し、実務用のライブラリ対応表を添える**方針を推奨。単一ファイル配布とオフライン動作を壊さないため。

## 調査で確認した 2026 年時点の前提

| 事項 | 状況 | 資料への影響 |
|---|---|---|
| WebGPU | 2026年1月に Baseline。Chrome/Edge/Firefox/Safari で既定有効（Safari は 26.0 以降）。グローバル対応率は 2026年3月時点で約 85% | Z層は「WebGPU 優先・WebGL2 フォールバック」を段階的強化の実例として扱える（M層 113 と同じ型） |
| サードパーティ Cookie | Chrome は**廃止を撤回**し継続。Safari・Firefox・Brave はブロック継続。Privacy Sandbox は 2025年10月に大半が終了し、**CHIPS・FedCM・Private State Tokens が残存** | 「iframe に埋めた社内サービスでログインが切れる」問題は今後も残る。CHIPS と Storage Access API を Y層で扱う必要がある |
| OAuth | OAuth 2.1 で **PKCE（S256）が必須**、implicit フローは廃止。アクセストークンはメモリ、リフレッシュトークンは HttpOnly Cookie。Electron はシステムブラウザ＋ループバック/ディープリンク＋`safeStorage` | Y層の認証項目はこの形を正とする（12 Electron リファレンスと接続） |
| WebHID / WebSerial / WebUSB | Chromium 系デスクトップのみ。Firefox・Safari・モバイルは非対応で、グローバル約 27%（2026年4月時点） | 現場機器連携は**Electron が本命**という結論を明示できる。X層の早見表に行を足す |
| 3D ファイル形式 | Web の標準は glTF / GLB。**STEP・IFC はブラウザで直接は開けず変換が要る**（IFC は web-ifc、STEP は OpenCascade 系のツール） | Z層は「glTF に変換して配る」を前提に据え、変換の話を独立項目にする |
| AR | `<model-viewer>` が WebXR / Scene Viewer / Quick Look を自動で切り替える（Android は WebXR/Scene Viewer、iOS は Quick Look） | AR は「単一の API では無い」ことを含めて 1 項目で扱う |
| 3D 操作の慣習 | オービット / パン / ズームの三点セット、右上のビューキューブでの視点スナップ、断面・計測・分解図・ホットスポットが標準機能 | Z層の項目立てを既存 CAD/ビューアの慣習に合わせる（名称を覚える資料としての一貫性） |

## 実装方針（要合意）

### 3D の依存方針：3案

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| **A. 完全自前** | WebGL2 の最小レンダラ（共通 `assets/mini3d.js` 約 300 行）を書き、全デモをその上に作る | 依存なし・単一ファイル配布が維持できる・**原理が全部見える** | 実装量が多い。写実的な描画はしない（業務用途では不要） |
| B. ライブラリ同梱 | three.js を同梱して使う | 実務に近い | 単一ファイルが 1.5MB 超に。ライセンス表記が要る。原理が隠れる |
| **C. 併用（推奨）** | 原理は A で自前実装し、各項目に「実務では three.js / model-viewer でこう書く」の対応コードを併記（実行はしない） | 原理と実務の両方が手に入り、配布物は軽いまま | 併記分の記述が増える |

**推奨は C。** 既存の 12（Electron）・13（kintone）と同じ「動くデモ＋実務コードの提示」の形になり、資料全体の一貫性も保てる。

### オフラインで実演できないもの

Y層の 117（3rd party Cookie）・119（OAuth）・120（Electron 認証）・123（Webhook）は、単一ファイルの中では**本物を動かせない**。12・13 と同じく「模擬＋実コード提示」とし、ページ冒頭にその旨を明記する。126（現場機器）は実機がある Chromium 系でのみ完走し、それ以外では非対応表示になる（X層 113 の型）。

## 確認したいこと

1. **3D の依存方針**：A / B / C のどれにするか（推奨 C）
2. **優先順位**：Y層（外部連携）と Z層（3D）のどちらを先に作るか
3. **3D の対象**：想定しているのは「部品・治具の閲覧と計測」までか、「配置・寸法の編集」まで踏み込むか（133 ギズモ以降の重みが変わる）
