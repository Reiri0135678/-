43無限キャンバス Infinite canvas（パン＋ズーム＋座標変換）

画面座標（ピクセル）とワールド座標（図面上の位置）を分けて持つ。表示は screen = world × scale + offset、入力は逆算 world = (screen − offset) ÷ scale。この2つの式だけで、パン・ズーム・クリック位置の特定が全部つながる。

操作：ドラッグでパン、ホイールでズーム（カーソル基準）、ダブルクリックでその位置に点を置く。右上にカーソルのワールド座標が出る。

44ズーム中心の維持 Zoom-to-cursor

「ズームすると見ていた場所がズレる」の正体は、原点基準で scale しているから。カーソル下のワールド座標を先に求め、scale 変更後も同じ点がカーソル下に来るよう offset を計算し直す。式：offset = cursor − world × newScale。

操作：方式を切り替えて、同じ位置でホイールしてみる。「原点基準」だと図がカーソルから逃げる。

45ミニマップ Minimap

全体を縮小して描き、現在の表示範囲を枠で示す。枠のドラッグでも移動できる。同じワールド座標を「別の縮尺」で描いているだけなので、43 の式がそのまま使える。

操作：大きい方をドラッグでパン、または右下のミニマップの枠をドラッグ。

46ノードエディタ Node graph / Wiring

ノード（箱）のポート同士を線で結ぶ。線は SVG のベジェ曲線 M x1 y1 C x1+d y1, x2−d y2, x2 y2。出力ポートからドラッグ→入力ポートで離すと接続。ノードを動かすと線を引き直す。

操作：右側の●から左側の●へドラッグして接続。ノード本体をドラッグで移動。線をクリックで削除。

47スナップ / スマートガイド Snapping / Smart guides

ドラッグ中、他要素の端・中心と一定距離（しきい値）以内なら、その座標に吸着してガイド線を出す。候補座標を全部列挙して「最も近いものが閾値内か」を見るだけ。

操作：青い箱をドラッグして灰色の箱の端・中心に近づける。Ctrl を押しながらだとスナップ無効。

50マルチタッチジェスチャー Pinch / Rotate / 2-finger pan

2本の指の「距離」「角度」「中点」の変化量から、拡大率・回転角・移動量を同時に求める。pointerId ごとに座標を Map で持てば、Pointer Events だけで書ける。

51修飾キーによる制約 Constrained drag（Shift / Alt / Ctrl）

ツール系アプリの共通作法：Shift=軸固定（水平か垂直のみ）、Alt=グリッド吸着、Ctrl=吸着解除。移動量の計算の最後に、押されているキーで補正を掛けるだけ。

操作：箱をドラッグしながら Shift / Alt を押す。

52状態機械駆動UI State-machine driven interaction

「押した」「動かした」「離した」を場当たり的に処理するとバグが出る。状態を明示（idle → pressed → dragging → idle）し、各イベントで「今の状態で何が起きたら次はどこか」だけを書く。押しただけ（pressed→idle）はクリック、閾値を超えたらドラッグ、と分岐が自然に決まる。

操作：箱をクリック／少しだけ動かす／大きく動かす。右の図で現在状態が光る。

53Web Animations API WAAPI

JS からアニメーションを生成し、一時停止・逆再生・速度変更・完了待ち（Promise）ができる。CSS transition では「途中で止めて戻す」が書きにくいが、WAAPI なら animation.reverse() の1行。

操作：ボタンで制御。「完了待ち」は await anim.finished の後にログが出る。

54描画ループ最適化 rAF batching

pointermove は 1フレームに複数回来ることがある（高レートマウス・タッチ）。イベントごとに描画すると無駄。「最新の値だけ保存し、描画は requestAnimationFrame で1フレーム1回」にまとめる。

操作：方眼の上でマウスを素早く動かす。イベント回数と描画回数の差を見る。

55Canvas 描画 Canvas rendering + ヒットテスト + devicePixelRatio

DOM要素を数万個作ると重いが、Canvas ならビットマップに描くだけなので軽い。代わりに「どれをクリックしたか」は自分で計算する（ヒットテスト）。高解像度画面では devicePixelRatio 分だけ内部解像度を上げないとぼやける。

操作：点の上にマウスを乗せると赤くなる（距離計算でヒット判定）。

58フォーカス管理 / ライブリージョン Focus trap / inert / aria-live

自作モーダルでは3つ必要：①開いたら中にフォーカスを移す ②背面を inert にして Tab が抜けないようにする ③閉じたら元の要素へフォーカスを戻す。非同期の結果は aria-live 領域に書くと読み上げソフトが通知する。

操作：開いて Tab を連打（外に出ない）→ 閉じると「開く」ボタンにフォーカスが戻る。

61Electron：フレームレスウィンドウの操作 -webkit-app-region

OS標準のタイトルバーを消して自前のヘッダーを作る場合、「ここを掴んだらウィンドウごと動く」領域を CSS で宣言する。ボタンなど押したい要素は no-drag で除外しないとクリックできなくなる。ブラウザでは効かないため、ここでは同じCSSを当てたモック（枠内でウィンドウを動かす模擬）を置いている。

操作：模擬ウィンドウのタイトルバーをドラッグ（Electron では本物のウィンドウが動く）。ボタン部分は掴めない。

62Electron：ネイティブメニュー / ショートカット Menu / accelerator / IPC

OSのメニューバー（ファイル・編集…）とショートカットはメインプロセスで定義し、押されたら IPC で renderer に通知する。renderer 側は「メニューから来た」「ボタンから来た」を区別せず同じ関数を呼ぶ設計にする。ブラウザでは動かないため、下のボタンで「メニューが押された通知が来た」状況を模擬している。

操作：「メニュー: 新規作成 を模擬」を押すと、renderer の受信ハンドラが動く。
