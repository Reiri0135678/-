# 05. 画面と API

## 画面（3 枚）

### 1. 投稿（`/post`）

タブレットで片手操作できることを優先。上から順に選ぶだけで投稿できる。

```
┌──────────────────────────────┐
│ 困りごと・提案を投稿          │
│ 区分   [困りごと] [改善提案]   │ ← 大きなトグルボタン
│ 場所   [第1ライン ▼]          │
│ タイトル [________________]   │ ← 必須。60 文字
│ 詳細   [                  ]   │ ← 任意
│ お名前 [________]  (任意)     │
│                [ 投稿する ]   │
└──────────────────────────────┘
投稿後: 「受け付けました（No.123）」→ 3 秒でフォーム初期化
```

### 2. ボード（`/`）

ステータスをカラムにしたカンバン。カードをタップで詳細。

```
受付(3)     検討中(2)   実施中(1)   完了(8)   見送り(1)
┌────────┐ ┌────────┐ ┌────────┐
│#123    │ │#120    │ │#118    │  ...
│区分/場所│ │        │ │        │
│タイトル │ │        │ │        │
│3日前   │ │        │ │        │
└────────┘ └────────┘ └────────┘
フィルタ: 場所 [すべて ▼]  区分 [すべて ▼]
```

詳細（モーダル）: 全項目表示 + ステータス変更 / 担当者 / 対応コメントの編集。

### 3. 集計（`/stats`）

- ステータス別件数（数字タイル 5 つ）
- 区分 × 場所 の件数表
- 直近 8 週の投稿数（棒グラフ）

## API（BFF）

すべて JSON。エラーは `{ "error": { "code": string, "message": string } }`。

| メソッド | パス | 用途 | 備考 |
|---|---|---|---|
| GET | `/api/health` | 稼働確認 | `mode: "kintone" \| "mock"` を返す |
| GET | `/api/options` | 選択肢 | kind / area / status |
| GET | `/api/posts` | 一覧 | クエリ: `status`, `area`, `kind`。`posted_at` 降順 |
| GET | `/api/posts/:id` | 1 件 | |
| POST | `/api/posts` | 投稿 | body: `kind, area, title, detail?, reporter?` |
| PATCH | `/api/posts/:id` | 更新 | body: `status?, owner?, response?`。完了 / 見送りで `completed_at` を自動設定 |
| GET | `/api/stats` | 集計 | byStatus / byKindArea / weekly |

### 投稿 body の検証（shared）

| 項目 | 規則 |
|---|---|
| kind | 選択肢のいずれか |
| area | 選択肢のいずれか |
| title | 1〜60 文字（前後空白除去後） |
| detail | 0〜2000 文字 |
| reporter | 0〜30 文字 |

## kintone とのマッピング

`shared/src/fields.ts` のフィールドコードのみを使う。kintone のレコードは
`{ title: { value: "..." }, ... }` 形式なので、server 側の `toPost` / `toRecord` で変換する。
